## 2. 기능 선정: 회당 최대 1건

1. **필요성·범용성:** 여러 사람이 실제로 자주 겪는 문제인지, 기존 페이지로 해결할 수 없는지 확인합니다. 특정 개인, 좁은 직군 또는 특수 상황만을 위한 후보는 범용성 부족 사유를 기록하고 제외합니다.
2. **최근 검색 수요:** 관련 검색어와 최근 조회 기간, 조회한 결과 링크를 기록합니다. 네이버 데이터랩이나 Google Trends의 상대 지수는 절대 검색량으로 표현하지 않으며, 조회하지 못한 수치는 추정하지 않습니다. 공식 문서가 있다는 사실이나 검색 결과에 페이지가 나온다는 사실은 수요 근거가 아닙니다.
3. **공식 근거:** 기관 원문 또는 공식 표준으로 구현 범위를 뒷받침할 수 있어야 합니다. 미발표 수치는 추정하지 않습니다.
4. 세 조건을 **모두** 충족한 후보 중 가장 유용한 것만 **최대 1건** 구현합니다. 적합한 후보가 없으면 **추가 없음**과 이유를 기록하고, 버그 수정·공식 수치 갱신·UX 개선에 시간을 씁니다. 근거가 새로 생기면 보류 후보를 다시 검토할 수 있지만, 기존에 명시적으로 거절된 건은 다시 추가하지 않습니다.

조사 허용 목록에는 `search.naver.com`, `ssl.pstatic.net`, `www.google.com`, `helpline.kdca.go.kr`이 등록돼 있습니다. 허용 여부와 실제 자료 조회 성공은 별개입니다.

## 3. 구현·감사·배포

- 브라우저 전용 도구가 조작 중 외부 요청을 하지 않는지 확인합니다. 방문자 집계나 추적은 추가하지 않습니다.
- `npm test`, `npm run audit`와 [README 배포 전 검수 체크리스트](../README.md#배포-전-검수-체크리스트)를 적용합니다. 정상·경계·오류 입력, 내부 링크·앵커, 콘솔, 복사·초기화와 레이아웃을 점검합니다. 검사 실패를 해결할 수 없으면 배포·완료 처리하지 않습니다.
- 확인한 파일만 커밋·푸시하고 Actions와 운영 주소를 확인합니다. 공개 메뉴·사이트맵·robots.txt에는 관리자 주소를 추가하지 않고 관리 탭의 `noindex,nofollow`를 유지합니다.

## 4. 결과 기록

- `src/admin-proposals.mjs`의 `latestFeatureReview`에 최근 점검 시각, 결과, 이유를 기록합니다. 후보에는 무엇·왜·공식 자료·범위·위험과 함께 `decision`으로 선정·제외 사유를 남기고, 운영 확인 후 `result: { label, url }`에 반영 결과를 기록합니다. 기존 이슈 URL은 과거 기록입니다.
- `src/admin-log.mjs`, `src/admin-audit-items.mjs`의 근거와 감사 Markdown을 동기화합니다. 모든 세부 요구에 검증 설명과 HTTPS 근거가 있어야 완료로 표시합니다.

## 5. 뉴스 예약 누락 시 보완 갱신

- 매 실행의 마지막 Pages 배포가 끝난 뒤, 추천 변경이 없었더라도 `gh run list -R everyhub/everyhub.github.io --workflow news.yml --event schedule --limit 5`로 최근 예약을 확인합니다. 직전 30분에 성공한 예약이 없고 뉴스·Pages 실행도 진행 중이지 않으면 `gh workflow run news.yml -R everyhub/everyhub.github.io --ref main`으로 보완 실행합니다. 실행 중인 뉴스·Pages 작업이 있으면 종료를 확인한 뒤 다시 판단합니다.
- `gh run list -R everyhub/everyhub.github.io --workflow news.yml --event workflow_dispatch --limit 5 --json databaseId,createdAt,status,conclusion,url`에서 방금 요청한 실행 ID를 찾아 `gh run watch <실행 ID> -R everyhub/everyhub.github.io --exit-status`로 종료를 확인합니다. 빌드 로그의 뉴스 건수·피드 실패 수와 배포 성공 여부를 기록합니다. 내용이 바뀌지 않아 배포가 생략됐다면 로그로 확인하고, 배포했다면 운영 뉴스 페이지를 확인합니다. 실패나 조회 불가도 기록하며, 수동 실행은 예약 성공으로 세지 않습니다.
- 이 절차는 하루 세 번 점검하는 보완 수단이며, 30분 갱신을 보장하지 않습니다.
